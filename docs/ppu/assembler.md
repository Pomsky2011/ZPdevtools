# ppuasm: the PPU assembler

```sh
ppuasm program.asm program.bin
```

The output is raw code, loaded at PPU address `$0000`, where the PPU starts running it. There are no directives: no `.org`,
no data bytes. Data is built by instructions, or by the program that loads the PPU (the layers microcode is generated by a
script for this reason).

## Syntax

| | |
|---|---|
| Case | instruction names and registers are case-insensitive |
| Registers | `R0`-`R63`; `SP` is `R61`, `PC` is `R62`, `DP` is `R63` |
| Numbers | decimal, `0x1F`, `$1F` or binary `0b101`; a leading zero means octal (`010` is 8). A literal with a stray character (`0b102`, `08`, `12abc`) is an error. `SETBYTE` refuses a plain number outside -128..255 (only a label is split into its low and high byte) |
| Comments | `;` or `#` to the end of the line. `//` is not a comment. |
| Labels | `name:` at the start of a line, on its own or before an instruction |
| Aliases | `R10 = COUNTER` makes `COUNTER` mean `R10`; `$0x0100 = IO` makes `IO` mean `0x0100` |

A **target register** number is 0-3, and a register id is 0-63 (0-15 where an instruction has only four bits, see
[instruction-set.md](instruction-set.md)).

### Labels and constants

`SETBYTE` writes 8 bits, so a 16-bit address takes two. When the operand is a **label**, the assembler chooses its low or
high byte according to the `TARREG` the target was last set with: a target aimed at `LSB` gets the low byte, one aimed at
`MSB` the high byte. A plain number is **not** split: `SETBYTE 3, 0x1234` stores `$34` whatever the target is aimed at, so
give a constant's two bytes separately.

```ppuasm
    TARREG 2, LSB, R59
    SETBYTE 2, handler     ; the low byte of handler
    TARREG 3, MSB, R59
    SETBYTE 3, handler     ; the high byte of handler
    NOP
handler:
    NOP
```

Loading a 16-bit constant takes four instructions and 8 cycles. Keep constants you use in a loop in registers.

## Target registers: the thing to know

The Preset E instructions work through four target registers (0-3). **Every shorthand that jumps to a label uses targets 0 and 1** and
leaves them pointing at `R62`. Use targets **2 and 3** for your own constants. Using 0 and 1 by hand is allowed, but the next
shorthand will overwrite them.

## Shorthands

A shorthand is not an instruction: it expands into the real ones. The exact expansion of each is in
[encodings.md](encodings.md), disassembled from the assembler's own output.

| Shorthand | Does | Uses targets 0 and 1? |
|-----------|------|------------------------|
| `JMR label` or `JMR 0xADDR` | jump to the label or address: loads `R62`, then `JMR` | yes |
| `JMZ` `JNZ` `JMG` `JNG` with a label | the conditional version of the same | yes |
| `PUSH RX` | `SP += 2`, then store `RX` at `SP` | no |
| `POP RX` | load `RX` from `SP`, then `SP -= 2` | no |
| `JSR label` | push a return address (the address after the whole expansion), then jump | yes |
| `RET` | pop the return address into `R62` and jump | no (but it overwrites `R62`) |
| `HLT` | an endless loop on itself | yes |

With no label, `JMR`, `JMZ`, `JNZ`, `JMG` and `JNG` are the plain one-word instructions that jump to whatever is in `R62`.

Things to remember:

- **`HLT` is a loop, not a halt.** The PPU keeps running (state "running"), spinning on one address. To really stop it, set
  bit 2 of `$00FD` or reset it from the CPU.
- **`PUSH`, `POP` and the stack in general use `SP` = `R61`**, which resets to `$8000`. The stack grows up and interrupts push on
  the same stack, so push and pop must stay balanced.
- **`JSR` and `RET` are 26 and 10 bytes.** A program that calls a lot spends its code space and cycles on the expansions; `CALL`
  with `DEFCALL` is a 2-byte call.
- **An interrupt can arrive between the `SETBYTE`s and the jump of a shorthand.** A handler that ends in `RET` leaves `R62`
  holding the return address, so a `JMR label` loop can be wedged on its own `JMR`. Wait for interrupts with a bare `JMR`
  that jumps to itself, as shown in [architecture.md](architecture.md). A handler that uses a shorthand that uses targets 0
  and 1 also overwrites them.

## Not in the assembler

No `.org`, `.db` or `.include`; no macros; no expressions beyond a single number, label or alias. Anything more is done by
generating the assembly, as `ucode/layers/gen_layers.py` does.
