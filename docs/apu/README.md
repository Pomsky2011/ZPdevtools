# APU: the audio processor

The APU is a small 8-bit processor, separate from the main CPU, with a hardware mixer (the **MMP**) that plays up to 16
sample channels and a stereo stream at 48 kHz. The CPU loads it with a program and sample data and it then runs on its own.

## In one screen

- **Two registers, `X` and `Y`**, both 8-bit. Everything else is a special register or memory.
- **Every instruction is 16 bits and takes 2 cycles.** 2.1 million instructions per second, 4.25 million in fast mode: about
  44 instructions per 48 kHz sample. There is no timer; delays are counted with `NOP n` stalls.
- **The stack grows up** and `SP` is 0 at reset, so initialise it with `BSP` before any call.
- **Jumps reach one 256-byte page** (`RP`). `JNZ` and `JMP` always push a return address.
- **Sample RAM is small:** 12,288 samples in all (256 ms at 48 kHz). Store samples at a low rate and raise the pitch; use the
  stream port for anything long.
- **No hardware envelopes.** Volume, pitch and pan change only when a program (or the sequencer) writes them.

## Three things that will bite you

1. **The APU is not reset when a cartridge starts.** The Boot ROM leaves it as its jingle engine did. Reset *and halt* it
   (`APUCTRL = $03`) before uploading, write the entry point to `APUPC`, then run (`$04`).
2. **`sta x, $yy` is a word write.** It re-writes the next address with its old value, which is a real write on a hardware
   register. See [instruction-set.md](instruction-set.md).
3. **A 16-bit MMP register applies on its high byte.** Write the low byte first.

## How these pages were checked

- [encodings.md](encodings.md) is generated by `scripts/gen_apu_docs.py`: each form is assembled with `apuasm`, split into
  its fields, and disassembled with `apudisasm`; a form that does not round-trip is reported.
- The mixer behaviour in [mmp.md](mmp.md) and [sst.md](sst.md) (loop points, one-shots, retriggering, the pan law, register
  read-back) was run against the emulator's mixer with the worked layouts from those pages.
- The programs in [programming-guide.md](programming-guide.md) were run on the emulator; `python3 scripts/check_doc_asm.py`
  assembles every `apuasm` block.
- Timing claims come from the emulator's constants (`src/apu.cpp`, `include/apu.h`).
